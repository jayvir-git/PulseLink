# PulseLink interrogate scope
Review the current uncommitted implementation, preserved in isolated snapshots. User wants verified defects in the full paramedic-to-hospital workflow and recent UI/accessibility changes.
Intent: a paramedic creates a draft, documents repeated observations/treatments and evolving notes without losing or duplicating work, advances allowed transport stages with a destination, and hands off an immutable clinical record. Only receiving hospital staff may see the appropriate incoming reports and acknowledge receipt. Queues reflect actual role-scoped receipt state. UI supports mobile, keyboard and readable interaction states. Report receipt is not transfer of clinical responsibility. Current known limitations are no offline draft recovery, save-time rather than actual clinical-event time, no structured full EHR fields. Do not report these intentional limits as new defects.

No production/source edits. You may add temporary repro tests/scripts in YOUR snapshot only. Use synthetic data, isolated browser contexts and local ephemeral servers; never modify the user's running browser/demo. Prefer existing browser test harness patterns. No live cloud services, no deployments, no git modifications.
For every candidate finding provide exact command, actual output, expected output/behavior, source path+line, severity and deterministic repro. Report only run-proven defects; list dropped candidates and reasons. Save report.md in your own reviewer directory. Parent will rerun each claimed failure independently. No scores. No fixes. Review bounds: prioritize up to 3 concrete failures per reviewer over broad speculative lists.
